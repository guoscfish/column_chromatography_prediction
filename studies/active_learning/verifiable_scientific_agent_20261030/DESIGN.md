# 最小可验证决策流程

`LLM Proposal → Deterministic Validator → Localized Repair → Verified Batch`

该流程是独立离线原型。生产 `validate_direct()`、NoCW `validate_plan()` 及其预算不变。宿主负责合法性与来源；LLM 负责实验选择、假设与解释。

## 一次提案后的处理

1. 固定完整候选 U_t、选前 L_t、pending、packet 哈希和期望数量。先检查输入快照自洽，拒绝集合重叠、重复标识、错误绑定。
2. 原规则判定是最终合法性基线。额外诊断一次列出重复位置、池外 / 已观测 / pending ID、数量缺口、字段路径和不合法证据；不再只返回第一个模糊错误。
3. 原响应只有一个完整无歧义 JSON 时，才能建立局部修复基础。合法候选与理由保持原样；保留不是立即接受，仍必须通过完整校验与最终冻结。
4. 错误候选要求 LLM 显式提供替换实验及理由；缺口要求补全；当前原型对数量超出要求完整重规划，由 LLM 决定保留哪些，宿主不自动删点。证据错误允许显式修改受影响假设及引用角色，保留其唯一ID与原合法观测引用的union；若需要更广泛删除或修改其他依赖，要求完整重规划。系统不自动挑点，不猜 ID，不把候选预测当实测依据。
5. patch 绑定原提案、冻结 packet、待改位置与内容。应用前验证版本与修复范围；应用后检查未授权字段没有变化、原合法选择被保留、选择唯一合法、引用闭合且证据全属 L_t。
6. 无法可靠解析结构、绑定已失效、不可判断原科学意图，或局部修改涉及广泛假设依赖时，标记完整重规划。不能用局部修复掩盖科学解释已经改变。
7. 修复后的完整方案重新走原 validator。真实运行仍需原有 freeze-before-reveal、来源证明和人工授权边界；mock 不能冻结正式实验。

批内重复时可以确定“同一真实 ID 出现多次”，却不能确定第二个位置原本想选什么实验。程序只能保留明确合法内容并请求缺口；删除重项后自行补随机点或 CW 点会改变科学计划，因此不允许。

## 哪些可直接确定性处理

| 情况 | 可自动处理 | 仍需科学推理 |
| --- | --- | --- |
| 严格单个 JSON 外层 code fence | 去掉唯一围栏，再走原 validator | 若内部仍错误，继续请求修复 |
| JSON 前后空白 | 原 JSON 解析器通常已处理 | 不构成新增算法收益 |
| 长 ID 定位 | 事前登记的双向唯一局部索引可精确解析 | 无有效索引时禁止猜测近似 ID |
| 重复、池外、已测、缺候选 | 自动检测并列出位置 / 缺口 | 由 LLM 选择具体合法替换 / 补点 |
| 非 L_t 证据、假设引用不闭合 | 自动检测关系错误 | 不能自动判断应改证据还是改命题 |
| 同分子多点、低距离、相似条件 | 自动计算已有描述指标 | 是否冗余、是否有对照价值、是否值得替换 |

没有确定性规则可以把一个不存在的哈希还原为 LLM 原本想要的化学实验。格式层修正不扩大为实验层自动修正。

## 候选定位

局部索引只是一种表示：由宿主按原 packet 的完整行顺序建立一对一表，并将表、原始 ID、顺序与 packet 哈希一起绑定。全池仍可访问，不排序、不截断，不加入高距离偏好。原有结构、条件、预测和数值信息列保持一致，NoCW 继续不提供 CW 列。

局部索引提供可证明的唯一解析，但是否降低 LLM 定位错误只能通过未来同状态对照验证；本次不能把已有坏哈希反向映射成索引。顺序保持可以排除代码主动引入的排序变化，却不能排除短编号的首因、位置或小数字偏好。未来对照需记录选择位置分布，并将索引效应与排序效应区分；不预设编号一定无行为影响。

索引不包含标签。宿主必须拒绝跨 packet 的旧编号、重复映射、篡改映射与非整数 / 越界编号。即使索引可解析，仍需重新检查真实 ID 的 U_t 归属、数量和证据。

## Numerical Critic 的位置

先得到合法计划，再把相同冻结状态与既有梯度表示交给只读 Critic。Critic 返回覆盖、冗余、条件匹配和可复核项，不输出任意加权总分、不强制替换。低几何距离与严格 loading 对照可以同时成立；科学目标与当前梯度表示可能不一致，应保留两类证据。

未来若允许 LLM 参考诊断修改合法计划，必须保存修改前后同状态候选、被改变的科学假设与标签预算，再用同状态训练对照评价。当前不接入 Free / NoCW，也不启动该实验。
