# 未来官方API与中转站比较：最小独立因子协议

**本轮仅设计，未发出任何API请求。** 当前历史相关性不足以认定中转替换模型、降低质量或丢失上下文。先核验客户端实际发送内容，再讨论服务端差异；服务商对比不能替代工程纠错保真修复。

## 主要问题与设计

分开研究两个因素：服务商（官方/指定中转）×候选展示顺序（历史固定顺序/预定随机置换）。采用完整2×2交叉，在同一冻结packet与同一科学任务内配对。历史Astra/Sol、不同effort、不同Prompt版本不能混为同配置复现。

建议最小材料为8个冻结状态，全部选自同一New CW协议。按预先声明规则，在候选身份错误层选择6例、证据成员资格错误层选择2例，层内按seed、round、首提议source排序取最早可用例；不得按Row Gain或最终实验结果选例。若某层不足则记录不足、缩小或重新预注册样本，不制造错误案例。保留31/32合法ID案例作为保真诊断，但它不是所有失败人群的无偏抽样。

每状态、每服务商、每顺序重复2次。分为两个独立任务：

1. **初次提议任务**：相同完整packet及相同系统指令，请求一份初始方案；不接新标签。
2. **控制纠错任务**：独立发送同一保存的错误assistant方案、同一完整packet、同一明确错误消息，要求按固定协议纠错。不使用各服务商新产生的不同错误方案作为主要纠错比较，因为那会使待修错误难度随服务商变化。

共8×2×2×2×2＝**128个未来逻辑请求**，另设严格物理传输重试上限且逐次记账。仅设计这一固定规模，不自动追加样本或追跑到出现显著差异。第一次结果与控制纠错结果分别统计；自然链式纠错可作为后续独立研究，不能与控制任务混合计算成功率。

## 输入等同性与顺序控制

- 在同一状态/顺序/任务内，两服务商的messages、模型请求名、thinking effort、采样参数、最大生成预算、工具和store设置完全相同。endpoint与凭据路由是唯一服务差异。请求的唯一模型版本须在未来执行前确认两端可支持；若需要alias、effort降级或预算替换，该单元判为不具备比较资格，不能静默继续。
- 从原packet只置换candidate rows；observed、pending、分子字典及所有数值保持不变。使用公开固定盐和状态ID生成SHA排序，预先保存两个完整展示ID顺序及hash。原展示顺序也已经是盐化顺序；实验检验的是位置依赖，不是“排序前有偏、随机后必定科学”。
- 每个顺序版本按原合同算法重新计算packet_sha。控制纠错材料只同步更新错误assistant方案的根packet_sha以绑定同一输入；保留全部候选ID、reason、hypothesis及所预定的真实错误不变。否则顺序因子会额外引入packet-binding错误，破坏独立性。
- 两端收到的控制错误消息逐字相同，由冻结错误诊断生成，不能包含“选择前32个”“全部重新选”等额外捷径。分别保存system/user/assistant/error的顺序、字节数、hash和序列化请求hash。
- 使用同一实际validator版本，明确direct、CW wrapper、NoCW wrapper的不同。不能把未运行paired协议的额外限制套在旧材料上。

## 预定评价指标

| 指标 | 固定定义与分母 |
|---|---|
| 初次合法率 | 初次任务中，32项、唯一、合法当轮候选、正确绑定、通过同一真实schema/evidence-membership gate的方案比例 |
| 控制纠错成功率 | 控制任务在一次逻辑纠错内通过同一gate的比例；不把服务商各自产生的不同错误混合 |
| 原方案保留率 | 纠错后仍保留的原合法唯一ID数÷控制错误方案原合法唯一ID数；另报reason/hypothesis逐值保留率 |
| 展示前缀率 | 最终ID集合恰等于当前展示前32的比例；另报有序相同率及原顺序前缀率，不能混用 |
| 科学保真 | 自动检查ID、文本、typed evidence的变动；语义有效性留盲审，不以schema通过代替科学正确 |
| 开销 | 每逻辑请求和每物理尝试的输入/输出/推理token、延迟、失败码、响应字节及账单可核对费用 |

技术重试与逻辑纠错分开：物理重试复发相同语义请求，逻辑纠错加入assistant错误方案及用户错误消息。保留所有失败attempt，不能只记录成功答案。模型服务返回的effective identity若未提供则记未知；客户端请求名和provider响应标识不等于后台权重的独立验证。

主要对比为同状态同顺序的服务商配对差、同状态同服务商的顺序配对差，并报告服务商×顺序交互。先逐状态展示2次重复，统计块以状态为单位；128个请求不是128个独立科研重复。8状态小样本仅作工程筛查，无强显著性结论。预先指定主指标为合法率和原合法选择保留率，其余探索性指标注明多重比较。

## 不做的归因

初始合法率不同可能来自服务约束、采样与响应截断，不自动意味着模型被替换。前缀率对顺序敏感说明位置关联，未必说明懒惰。纠错成功但保留率低仍属于方案漂移。上述实验没有新标签或重训，无法判断Row Performance改善。

费用在执行前按实际可核对单价和token上限另算并授权，当前不假造官方支持列表、价格或账单。若两端无法锁定同一模型/effort/输入预算，优先完成客户端局部纠错工程验证，暂缓服务商质量比较。
