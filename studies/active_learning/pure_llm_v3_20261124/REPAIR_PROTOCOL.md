# 局部修复协议

V3 沿用十月三十日可验证规划原型的全量诊断、整槽替换、锁定合法实验和完整复验方式。每次诊断包含零基槽号或字段路径及类别，并区分当前已观测、其他候选状态、未知和重复等 ID 问题。正确的当前候选身份可独立锁定，即使同槽的分子、anchor 或证据需要修订。

宿主根据原提案、完整请求绑定和诊断计算修复合同，并生成供模型回传的短 `repair_id`。外发视图只包含所需的结构化状态和诊断，宿主保留未通过校验的原提案并检查合同。诊断可以返回错误 ID 与准确条件轴。未识别的响应字段及任意错误值不被拼入纠错提示。传输层额外把本次回复绑定到物理请求、原 packet、模型 checkpoint、seed 和轮次。

模型返回 `replace_choices`、`append_choices`、`replace_hypothesis_updates` 和 `replace_fields`，每个可替换位置仅接受一次完整替换。身份非法时，模型写出新实验的完整理由与证据。合法选择及其理由原样保留；合法候选但关系错误时保持其候选身份以及仍然有效的结构化引用。假设修复维护稳定身份并保留有效证据。数量不足时，只接受模型明确提供的足量补充；数量超额、无完整合法 choice 或存在无法定位的结构问题时，必须显式进入重规划。重规划使用独立逻辑请求预算。模型也可通过 `mode: replan` 并说明原因，指出局部修复会破坏整体设计。

宿主检查精确修复范围和原合同绑定，再用完整 validator 检查修复稿。越权替换、证据丢失、跨状态响应和持续无效修复会留下失败记录。科学意图是否在修改后保持，通过模型理由和独立科学审阅评估。只有最终接受的计划可写入冻结记录，历史标签和模拟反馈均无须在修复过程中打开。
